## 1. What was evaluated

The Library Research Brief agent: a multi-agent pipeline that decomposes a
research question into sub-questions, runs parallel retrieval per sub-question,
synthesizes a structured brief, and reports gaps where the library cannot answer.

The eval measures whether the agent's output is better than a single-pass
synthesis on six quality dimensions: does it answer what the user asked, does it
cite real articles, does it correctly identify gaps, does it synthesize rather
than list, does it surface tensions, does it expand usefully without scope creep.

---

## 2. Variants

**A — baseline (single-pass synthesize_topic)**
One hybrid search on the raw question. Title + description + one highlight per
article. No sub-question decomposition. No gap report. This is what the app
produced before the research brief feature.

**B_old — research brief v1**
Lead agent decomposes into sub-questions. Parallel subagent retrieval with all
highlights. Engagement weighting in context construction. Structured brief with
gap report. Rubric v1 (six dimensions including `sub_question_coverage` matched
against a fixed expected sub-question list).

**C — research brief v1 + retrieval improvements + rubric v2**
Same agent architecture as B_old, with four targeted fixes:
1. Planner prompt rewritten — sub-questions derived from the question, not anchored to library titles
2. Multi-query expansion — 2 extra query variants per sub-question to bridge vocabulary gaps
3. Chunk fallback — articles with empty/thin descriptions get a real text chunk for the relevance filter
4. `verify_synthesis` — fabricated gaps stripped (gaps on sub-questions with `coverage: full` or `coverage: partial`)

Rubric upgraded to v2 (see §4).

---

## 3. Dataset

21 research questions grounded in the real dev library (~360 articles). Each case
is hand-labeled with:

- `core_intent` — one sentence describing what the user actually wants
- `legitimate_expansions` — angles that add value if the library supports them
- `off_limits_expansions` — scope creep to penalize
- `expected_sub_qs` — the sub-questions a good decomposition should produce
- `answerable_from_library` / `unanswerable_sub_qs` — which sub-questions the library can and cannot answer
- `key_article_titles` — articles that must appear in the brief
- `ideal_coverage` — `full` | `partial` | `thin`

Six structural categories:

| Category | Count | What it tests |
|----------|-------|---------------|
| MULTI_ANGLE | 4 | Both sides of a debate must be found and named |
| VOCAB_DIVERGE | 4 | Same topic stored under different vocabulary |
| PARTIAL_COVER | 4 | Library covers some sub-questions but not others; gap report required |
| SINGLE_ANGLE | 2 | One tight sub-topic; brief must stay narrow |
| TENSION | 4 | Library contains contradictory takes that must be surfaced |
| ENGAGEMENT_BIAS | 3 | High-engagement articles exist; brief should weight them |

All 21 cases run against the real library in a live Postgres session. No synthetic
articles. Sub-questions and briefs are generated by the actual pipeline code.

## 4. Rubric (v2)

G-Eval LLM-as-judge. Six dimensions scored 1–5 by GPT-4o with chain-of-thought
steps, normalized to 0–1.0, then weighted. Pass threshold: 0.70.

| Dimension | Weight | What it measures |
|-----------|--------|-----------------|
| `question_fidelity` | 0.25 | Does the brief answer what the user actually asked? Judged against `core_intent`, not the expected sub-question list. |
| `useful_expansion` | 0.10 | If the brief expands beyond the minimum, is that expansion genuinely additive? |
| `source_grounding` | 0.25 | Are claims tied to specific retrieved articles? Do key articles appear? |
| `gap_accuracy` | 0.20 | Does the `gaps` array correctly report topics the library cannot answer, without false entries? |
| `synthesis_quality` | 0.10 | Does the brief synthesize across sources, or list article summaries in sequence? |
| `tension_surfacing` | 0.10 | Are contradictions named explicitly with the articles on each side? |

**Hard fail conditions** (override score regardless of weighted total):
- `fabricated_citation` — brief cites an article ID not in the retrieved set
- `no_gap_report` — case has unanswerable sub-questions but `gaps[]` is empty
- `zero_source_grounding` — no article titles cited in a library with relevant content

**v1 → v2 rubric changes**

v1 had `sub_question_coverage` (weight 0.30): awarded points for matching an expected
fixed list of sub-questions. This penalized valid alternative decompositions — a brief
that covered the core intent with different sub-questions still scored poorly.

v2 replaces it with:
- `question_fidelity` (0.25): judged against `core_intent`, a one-sentence description
  of what the user actually wants. Any decomposition that serves core_intent scores 5.
- `useful_expansion` (0.10): rewards expansion into `legitimate_expansions`, penalizes
  expansion into `off_limits_expansions`.

`gap_accuracy` was also rewritten: v1 derived gap topics from sub-question index
positions (fragile, wrong when the brief used different sub-questions). v2 passes topic
descriptions directly, judges by substance not wording, and instructs the judge to
look only at `brief.gaps[]` — not at `coverage_assessment: none` in findings, which
caused false penalization when retrieval missed articles the library actually had.

## 5. Pipeline changes in variant C

### 5a. Planner prompt — no title anchoring

**Problem:** The planner was seeded with library article titles to calibrate
sub-question count. The model drifted: sub-questions echoed title vocabulary
("What does 'AI Doesn't Reduce Work' say about...") rather than deriving from
the question. This caused vocabulary-locked retrieval — the sub-question matched
the title it was anchored to, but missed semantically equivalent articles stored
under different vocabulary.

**Fix:** Titles used only to count relevant articles for calibration
(< 3 → 2-3 sub-questions, 3-6 → 3-4, 6+ → 4-5). Sub-questions must derive from
the question's structure, never from title vocabulary.

**Observed effect:** Sub-question quality improved on VOCAB_DIVERGE cases
(`ai_cognitive_load`, `context_engineering_agents`). Sub-questions became
question-derived ("How has AI been reported to reduce mental work?") rather than
title-anchored ("What does 'AI Doesn't Reduce Work' say?").

### 5b. Multi-query expansion

**Problem:** Personal reading libraries store content under the vocabulary the
user encountered. An article about cognitive load from AI might be tagged
"context engineering," "attention management," or "AI fatigue" depending on how
the user encountered it. A single sub-question phrase anchored to one vocabulary
cluster misses articles stored under others.

**Fix:** For each sub-question, the subagent calls the LLM once to generate 2
alternative phrasings, then runs all 3 queries through hybrid search and unions
results by article ID before the relevance filter.

```
sub_question: "How has AI been reported to reduce mental work in various industries?"
→ alt_1: "Ways AI automates cognitive tasks and reduces mental burden"
→ alt_2: "AI impact on workload and mental effort in the workplace"
→ union of all 3 search results → deduplicated by ID → relevance filter
```

Adds ~1 LLM call per sub-question (cheap, structured, 128 tokens max).

### 5c. Chunk fallback for thin descriptions

**Problem:** 18% of the library (65/360 articles) have descriptions shorter than
60 characters (empty field, generic byline, or scraper artifact). These articles
return only title + empty string to the relevance filter, which then correctly
excludes them — but they may be genuinely relevant. Key articles (`Pluralistic:
LLMs are slot-machines`, context engineering articles) were affected.

**Fix:** For any article with `len(description) < 60`, the subagent fetches one
text chunk from `content_chunks` before building the candidate list. The chunk
snippet (first 120 chars) replaces the empty description in the relevance filter
prompt. Articles the filter would have excluded due to no description now get
judged on actual content.

### 5d. Fabricated gap stripping in verify_synthesis

**Problem:** The LLM synthesizer sometimes reported gaps for sub-questions that
were actually answered. The model's parametric knowledge suggested "there must be
other organizations working on AI safety beyond what I found" — and generated a
gap entry even when the subagent had found 6 relevant articles with
`coverage: full`. v1 only stripped citations not in the retrieved set, not gaps
on answered sub-questions.

**Fix:** `verify_synthesis` now strips any gap entry whose sub-question maps to a
subagent result with `coverage_assessment` of `full` OR `partial`. Only
sub-questions with `coverage: none` are legitimate gap candidates. Gaps for
answered sub-questions are parametric hallucination and are removed before the
brief is stored.

The gap injection logic (which injects a gap entry for any `coverage: none`
sub-question that the synthesizer forgot) is unchanged and runs after stripping.

## 6. Results — full 21-case pilot

| Variant | Avg score | vs A |
|---------|-----------|------|
| A (baseline) | 0.605 | — |
| B_old | 0.515 | −0.090 |
| **C** | **0.744** | **+0.139** |

C beats A by +0.139 and B_old by +0.229 across all 21 cases.

B_old regressed against A (−0.090): the agent architecture was correct but the
rubric v1 punished valid alternative decompositions. The v2 rubric correctly
scores intent-serving briefs; C's higher absolute scores reflect both rubric
accuracy and real pipeline improvements.

One regression vs B_old: `us_trade_policy_tariffs` (C=0.500, B=0.575, −0.075).
Root cause: thin library (1 article on tariffs), synthesis and tension_surfacing
both 1/5, gap_accuracy 1/5 (gaps empty but library_cant_answer has 2 unanswerable
sub-questions). The pipeline generates a brief from one article but doesn't inject
the missing gap entries reliably when the synthesizer produces a complete-looking
but shallow brief.

## 8. Failure taxonomy

**Gap injection misses (gap_accuracy 1/5 despite pipeline fix)**
Cases: `ai_labor_displacement`, `glp1_evidence_vs_hype`, `forward_deployed_engineer`,
`ai_alignment_safety`, `music_streaming_culture`, `us_trade_policy_tariffs`.

The synthesizer produces findings for all sub-questions (even thin coverage) and
marks them as having some coverage, which causes `verify_synthesis` to strip any
gap entries for those sub-questions. But the coverage is too thin to count as
`partial` — it's really `none` that the subagent misclassified as `partial`.

Root cause: the subagent's self-assessed `coverage_assessment` is noisy. An article
that mentions a topic tangentially gets marked `partial` when the correct label is
`none`. Fixing this requires calibrating the coverage assessment prompt or adding a
second-pass coverage check.

**Tension surfacing failures (tension_surfacing 1/5)**
Cases: `us_foreign_policy_iran`, `forward_deployed_engineer`.

The brief found the relevant articles and produced correct findings, but did not
name the contradiction explicitly. The synthesis prompt doesn't strongly enough
require naming contradictions with specific article attributions for TENSION cases.

**Off-limits expansion (useful_expansion 1/5)**
Cases: `ai_engineer_career`.

Planner generated a sub-question about "ethical considerations in AI engineering"
which is in the `off_limits_expansions` list and not grounded in library articles.
The planner prompt's rules around staying within the question's scope aren't
enforced strongly enough for ENGAGEMENT_BIAS cases.

**Single-angle fidelity drift (question_fidelity 3/5)**
Cases: `star_interview_method`, `us_foreign_policy_iran`.

For thin SINGLE_ANGLE cases, the planner generates extra sub-questions to fill
out the brief, but those sub-questions go beyond the one article's content scope.
The planner rule "for thin coverage, 2-3 sub-questions max" isn't being enforced
when the question sounds broad.

## 9. Rubric evolution

Three rubric versions over the course of this eval:

**v1 (initial):** `sub_question_coverage` (0.30) matched generated sub-questions
against a fixed expected list. Led to B_old regression: valid briefs with different
decompositions scored 1/5 on this dimension even when they answered the question
correctly. B_old averaged 0.515 vs A's 0.605 — the rubric was penalizing the
pipeline, not measuring it.

**v2 (intent-based):** Replaced `sub_question_coverage` with `question_fidelity`
(0.25) + `useful_expansion` (0.10). `question_fidelity` judges against `core_intent`
(a one-sentence description of user intent), not a fixed list. `useful_expansion`
uses `legitimate_expansions` / `off_limits_expansions` to reward or penalize scope.
Also added `core_intent`, `legitimate_expansions`, `off_limits_expansions` fields
to all 21 dataset cases.

**v2 gap_accuracy fix:** Initial v2 `gap_accuracy` CoT said "list every gap or
unanswerable item" — judge interpreted `coverage_assessment: none` in findings as
gap entries. Fixed to "look ONLY at `brief.gaps[]`" and added explicit rule:
"if library_cant_answer is empty and gaps is empty, score 5."

---

## 10. Decision

**Ship variant C.** Primary metric (weighted rubric score) improved +0.139 vs A
(the real baseline) and +0.229 vs B_old. 17/21 cases improved vs A, 20/21 improved
vs B_old. One regression vs B_old within noise (−0.075 on thin-library case).
No hard fails (fabricated citations, zero grounding) in any run.

**Remaining known issues (not blocking):**
- Gap injection unreliable for thin-coverage sub-questions: subagent
  `coverage_assessment` noisy on tangential matches
- Tension surfacing fails for TENSION cases when both articles are found but
  the synthesizer doesn't name the contradiction
- Off-limits expansion on ENGAGEMENT_BIAS questions: planner adds scope beyond
  the question when the question sounds broad

These are improvements for the next eval cycle, not defects in the shipped variant.
